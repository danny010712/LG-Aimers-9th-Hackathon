# 강의 7. LG AI연구원 해커톤 문제 소개 🔥🔥🔥

> 주최: LG 트윈스 데이터분석팀 (LG Aimers 9기 × LG 스포츠)
> **과제: "좋은 제구란 무엇일까?" — 투수의 다음 투구 제구 성공 확률 예측**
> 성격: **대회 본체.** 이 문서가 최우선. 강의1(Tabular)·강의4(시계열)와 직결.

**중요도 범례**: 🔥 해커톤 핵심 / ⭐ 중요 / 📎 참고

---

## 0. 문제 한 줄 정의 🔥🔥

**투구 단위(pitch-level) 데이터로, 다음 투구가 "제구 성공"일 확률을 예측하는 이진분류(확률 출력) 문제.**

| 항목 | 내용 |
|---|---|
| **Task** | Binary classification → **확률(0~1) 제출** |
| **Target** | 제구 성공 여부 (정의는 별첨 컬럼 자료 확인 필요 ⚠️) |
| **학습 데이터** | 2019~2024 시즌 (6시즌), Target 포함 |
| **평가 데이터** | 2025 시즌, **Target 비공개** (hidden test) |
| **평가 방식** | 제출 확률 vs 운영진 보유 정답 비교 (지표는 규정 확인 ⚠️, 확률예측이므로 AUC/LogLoss/Brier 유력) |
| **ID** | 선수명 없음. **익명 ID**(투수ID·타자ID·팀ID) |

---

## 1. 배경 — 왜 이 문제인가 ⭐

- 기존 제구 지표의 한계:
  - **ERA(평균자책점)**: 결과만, 과정 설명 못함.
  - **BB%(볼넷비율)**: 제구 추정하나 맥락 빠짐.
  - **K%(탈삼진비율)**: 구위 중심, 제구와 다른 차원.
- → **결과 숫자만으론 "제구가 좋다"를 설명 못함.** 투구 단위로 제구 성공 확률을 모델링해 **맥락 있는 제구력 평가**를 만들자는 것.
- 야구 패러다임: 경험·직관 → **트래킹 데이터(Trackman/HawkEye) 기반 의사결정.**

## 2. 제공 데이터 구조 (4개 축) 🔥🔥

| 축 | 내용 | 피처 예시 |
|---|---|---|
| **① 경기 상황** | 언제·어떤 상황 | 볼/스트라이크/아웃, 이닝, 점수차, 주자 상황 |
| **② 경기 중요도** | 얼마나 중요한 순간 | **기대승률(Win Expectancy)**, **상황 중요도(LI, Leverage Index)** |
| **③ 과거 이력** | 지금까지 어떻게 던졌나 | **asof_\* 누적통계**, 최근 경기 성과, 과거 구종 사용 패턴 |
| **④ Trackman 과거 로그** | 공의 물리적 특성 | 구속(velocity), 회전수(spin), 무브먼트(수평·수직), 릴리스(위치·익스텐션) |

- 세부 컬럼은 **별첨 자료** 참고 (본 발표엔 미기재). → **반드시 별첨 컬럼 정의 확보** ⚠️.
- **asof_\* = as-of 시점 누적** → 미래정보 누수 방지 설계 신호. 좋음.

## 3. 예측 결과의 활용 (문제 의도) ⭐

투구별 확률 → 상황별 누적 → **투수 제구력 평가**:
- 상황별 제구력(주자·카운트·이닝·후반), 제구 안정성(최근 흐름·압박 대응·변동성), 선수 평가·육성.
- 코치 질문 예: "클러치에 강한가?", "불리한 카운트에서 승부 가능?", "7회까지 맡길 수 있나?", "오늘 등판 적절?"

## 4. 주최측 기대 🔥 (평가 2축)

1. **정확한 예측**: Hidden test 일반화 성능. 객관적 성취. → **리더보드 점수.**
2. **새로운 분석 아이디어**: 미처 못 본 변수·새 피처·다른 각도 모델링. **"운영진이 생각 못한 새로운 제구력 평가법"** = 가장 기대하는 결과물.

→ **점수 + 인사이트 둘 다.** 오프라인(Phase III)은 발표·아이디어 비중 큼 예상.

## 5. 내 분석 & 전략 🔥🔥 (핵심)

### 5-1. 문제 성격 진단
- **전형적 tabular 이진분류 + 확률 출력** → **강의1 Tabular ML 파이프라인 그대로 적용.** GBDT가 1순위.
- **시계열·누적 성격** 존재(asof, 최근 흐름, 시즌 순서) → **강의4 시계열 검증 원칙 필수.**
- 데이터 규모 큼(6시즌 투구 단위 = 수십만~수백만 행 추정) → **TabPFN(≤10K)은 부적합**, LightGBM 중심.

### 5-2. 검증 설계 (가장 중요) 🔥🔥
- **시간순 split 필수.** Train=2019~2024, Test=2025 → **2025를 모사하려면 2023~2024를 validation**으로 홀드아웃. 랜덤 KFold 금지(누수·시즌 분포 변화 무시).
- **누수 원천 차단** ⚠️:
  - asof_\* 이외에 **미래 정보 새는 피처 배제**(예: 그 경기/그 투구 결과 파생).
  - 같은 타석·경기 내 투구가 train/val 갈리면 정보 누수 → **경기ID/날짜 기준 GroupTimeSeriesSplit** 고려.
- **분포 변화(2025 신인·규정)** 대비 → 시즌 간 안정적 피처 선호.

### 5-3. 모델 🔥
- **베이스라인: LightGBM** (대용량 빠름). + XGBoost, CatBoost 앙상블.
- **CatBoost 주목**: 투수ID·타자ID·팀ID = **고cardinality 범주형** → CatBoost 자동 처리 or **target encoding(시간순 fold 내 fit, 스무딩)** 으로 누수 방지.
- 확률 예측이므로 **calibration** 신경 (LogLoss/Brier면 특히). isotonic/Platt, 또는 LightGBM `objective=binary` 기본 확률.

### 5-4. 피처 엔지니어링 (승부처, 주최측도 강조) 🔥🔥
| 방향 | 아이디어 |
|---|---|
| **카운트 상태** | ball-strike 조합, 유불리(투수 유리/불리), 3-2 풀카운트 플래그 |
| **상황 압박** | LI·기대승률 구간화, 주자 상황(득점권), 이닝·점수차 상호작용 |
| **최근 폼(rolling)** | 최근 N구/N경기 제구성공률, 구속·회전수 이동평균·표준편차(변동성) |
| **투수 특성** | asof 통산 제구율(스무딩), 구종별 제구 경향, 릴리스 일관성(분산) |
| **물리량** | 구속·회전수·무브먼트·익스텐션, 구종 추정, 이전 투구 대비 변화량 |
| **매치업** | 투수ID×타자ID 상호작용(희소→target enc), 좌우 상성 |
| **피로도** | 투구수 누적, 이닝, 경기 후반 플래그 |
| **직전 투구** | lag 피처(직전 구종·결과·로케이션), 연속 볼/스트라이크 |

- **"새로운 제구력 지표"** 아이디어(보너스): 상황·압박 보정 제구력(기대 대비 초과 제구), 변동성 지표 → 발표용.

### 5-5. 워크플로우 🔥
```
1. 별첨 컬럼 정의·Target 정의 확보 → verify: 제구성공 정의·평가지표 확정
2. EDA: 제구성공률(클래스밸런스), 결측, 시즌별 분포 변화, ID 분포 → verify: 누수 후보 컬럼 식별
3. 시간순 split 세팅(2023-24 val) → verify: val이 2025 모사하는지
4. LightGBM 베이스라인 + 지정지표 CV → verify: 안정적 점수
5. 피처 엔지니어링(위 표) 반복 → verify: val 점수 향상
6. 범주형 처리(CatBoost/target enc, fold내 fit) → verify: 누수 없음
7. Optuna HPO(시간순 CV) → verify: 과적합 없음
8. 앙상블/블렌딩 + calibration → verify: LogLoss/Brier 개선
9. 제구력 평가 인사이트 도출(발표용) → verify: 새 관점 제시
```

### 5-6. 리스크·체크포인트 ⚠️
- [ ] **Target "제구 성공" 정확한 정의** (존 통과? 의도 위치? 스트라이크?) — 별첨 확인 최우선.
- [ ] **평가지표 확정** (AUC vs LogLoss vs Brier) → 그 지표에 직접 최적화.
- [ ] **누수**: 미래·당구 결과 파생 피처, 타석 단위 split 오염.
- [ ] **시즌 분포 shift**(2025) → 시간순 검증·강건 피처.
- [ ] **고cardinality ID** 처리(target enc 누수, 신규 ID 대응).
- [ ] **확률 calibration**.
